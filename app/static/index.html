1 · Upload source documents

Each file is parsed into structured blocks with page and bounding box, then stored as source_spans. Everything downstream cites a span, never a raw file — that's what makes “verify this claim” a database query instead of a re-reading exercise.

Upload & parse

Parser chain, cheapest correct parser first: pypdf_text (real page numbers) → anydoc (Rust, no ML model — office formats) → vision_llm_ocr (scanned pages, via a multimodal LLM). No parser in this chain downloads a model.

Ingested documents

Loaded from the database — already-parsed documents survive a page reload, so a demo never has to re-run a parse.

2 · Extract curriculum structure

An LLM proposes topics, subtopics, objectives and prerequisite edges from the syllabus text. Every node lands tagged machine_extracted with confidence below 1.0 — a machine-inferred prerequisite must never look as authoritative as one stated in the official syllabus.

3 · Parse questions & mark schemes

Exam questions and their mark-scheme entries are extracted as one linked entity, with marks and span-level page attribution on both halves. The unmatched counts are the parser's honesty signal.

4 · Map questions to objectives

An ensemble — embedding similarity, lexical retrieval, syllabus terminology and LLM classification — produces multi-label weighted mappings with confidence, not single-label classification. One question can legitimately assess several objectives.

5 · Teacher corrections

A correction is logged verbatim to teacher_corrections and, for a mapping, also overwrites the live row: confidence pinned to 1.0, method set to human_corrected. This history is the compounding asset — the one signal the ensemble always trusts.

6 · Historical assessment emphasis

A weighted score per objective — frequency, recency decay, marks, syllabus weighting and structural similarity — not raw frequency counting. This is what tells the solver which objectives actually earn teaching time.

7 · Calendar & timetable

The calendar is modelled as available instructional capacity, not a flat list of dates. A school day is not a slot — the solver needs derived available minutes per subject, class and date.

8 · Build the term plan

The solver places lightweight teaching units onto calendar capacity under hard constraints — prerequisite order, non-teaching days, window capacity. Lesson content is generated only after a unit has a slot, never speculatively.

9 · Disruption & replan

The point of a good replan is how little it disturbs, not how clever the rearrangement is. Churn against the previous plan is a first-class objective in the solver, not a post-hoc report.

10 · Grounded generation

Verify-then-render, not generate-then-cite: retrieve evidence → generate structured claims → verify each claim against its cited spans with a different model → reject the unsupported. A claim is never stored as verified unless the verification chain actually said so.
